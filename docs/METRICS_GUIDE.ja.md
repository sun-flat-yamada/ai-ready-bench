# メトリクスガイド＆評価基準

本書では、`aiready-benchmark` で算出される各メトリクス、その背景にあるアルゴリズム、および目標基準値（しきい値）について解説します。

## 2. 各メトリクスの詳細解説

### 1. 構造忠実度（Structural Fidelity: TEDS）
- **解決する課題**: ドキュメントのレイアウトが完全に崩れていても（例：表のセルが平坦化されてただのテキストの羅列になっているなど）、単純な BLEU や ROUGE などのテキスト類似度スコアでは高得点が出てしまう問題。
- **評価メカニズム**: 生成された Markdown は `markdown-it-py` により抽象構文木（AST）にパースされます。各ノードは型付きの構造要素（`heading`, `table`, `thead`, `tr`, `td`, `img`, `paragraph`, `list`）に分類されます。動的計画法によるシーケンスアライメントを用いて、候補 AST を正解 AST に変換するために必要な最小木変換操作を計算します。

### 2. テーブル忠実度スコア（Table Fidelity Score）
- **解決する課題**: テーブル枠の欠損や結合セルの誤認識は、RAG 検索における致命的なハルシネーション（もっともらしい嘘）の原因となります。
- **評価メカニズム**:
  1. **テーブル数の一致度**: $\frac{\min(N_{\text{pred}}, N_{\text{gold}})}{\max(N_{\text{pred}}, N_{\text{gold}})}$
  2. **次元の一致度**: 行数・列数の差異に対してペナルティを適用。
  3. **内容の重複度**: 正規化されたセルテキスト集合の Jaccard 類似度。

### 3. 画像パイプラインとケバブケース意味的リンク
- **解決する課題**: メタデータのない画像はテキスト LLM にとって理解不能であり、リンク切れの画像パスは下流のマルチモーダル取り込みを破壊します。
- **評価メカニズム**:
  - **抽出率**: コンテナ（DOCX の図面、PPTX の画像シェイプ、PDF の XObject、Visio のメディア）に埋め込まれた図表が物理的にディスクへ保存されているかを検証。
  - **ケバブケース命名規則**: ファイル名が英小文字・数字・ハイフン区切りに厳密に一致しているかを検証。`img_001.png` や `Slide2.JPG` のような恣意的な命名は不合格となります。
  - **リンク整合性チェック**: Markdown 内のすべての `![alt](images/filename.png)` リンクが、実際のファイルシステム上のファイルと照合されます。存在しないファイルを指すリンクがある場合、リンク切れとして検出されます（ペナルティ 100%）。

### 4. ノイズ比率とクリーン度（Noise Ratio and Cleanliness）
- **解決する課題**: 一部のコンバーターは未パースの HTML の塊（`<div class="header">`, `<span style="...">`）をそのまま吐き出し、これがトークン数を膨張させ LLM の推論を混乱させます。
- **評価メカニズム**: 未処理の HTML タグ（標準 Markdown 互換の表タグを除く）、制御文字（`\x00` 〜 `\x1f`）、および過剰な空行を検出します。

### 5. コストとトークン経済モデル（Cost & Token Economic Modeling）
- **解決する課題**: トークン数を 40% 膨張させる取り込みパイプラインは、企業の年間 LLM API コストをそのまま 40% 増加させます。
- **評価メカニズム**: `tiktoken` の BPE エンコーディングを用いて正確なトークン数を測定します。以下のモデルに基づき、1,000 ドキュメントあたりの入力コスト試算をモデル化します：
  - **GPT-4o**: \$2.50 / 100万入力トークン
  - **Claude 3.5 Sonnet**: \$3.00 / 100万入力トークン
  - **Gemini 2.0 Flash**: \$0.10 / 100万入力トークン
  - **DeepSeek-V3**: \$0.14 / 100万入力トークン
