# マルチペルソナレビュー＆システム改善レポート

本ベンチマークフレームワークが実世界のエンタープライズ、運用性、および科学的厳密性の要件を満たすことを保証するため、開発プロセスにおいて 4 つの異なるエンジニアリングペルソナによる査読とシステム改善を実施しました。

---

## ペルソナ 1: シニア LLM & RAG ソリューションアーキテクト

### ペルソナの背景
大規模な検索拡張生成（RAG）およびマルチモーダルエージェントアーキテクチャの設計を担当。トークンの肥大化、チャンキングの分断、失われたテーブルの意味構造、およびハルシネーションを引き起こす図表コンテキストの欠落に極めて敏感。

### レビュー指摘事項と致命的フィードバック
> *「BLEU や Levenshtein のような単純なテキスト類似度メトリクスは、RAG にとって何の役にも立ちません。もし Office パーサーが表のセルをランダムな順序で書き出したり、複数レベルの見出し `# 見出し 1` をただの太字 `**見出し 1**` に変換してしまったら、チャンカーはセクション境界を完全に見失ってしまいます！さらに、図表は意味のあるファイル名でクリーンにリンクされていなければなりません。もし画像が `img_001.png` として抽出されただけで Markdown から一切リンクされていなければ、マルチモーダルエージェントはそのコンテキストを見つけることができません。」*

### 実装されたアーキテクチャの改善
1. **木編集距離類似度（Tree Edit Distance Similarity: TEDS）**: 表層的な文字列比較を廃止し、コンテナのネスト、見出しレベル、テーブルブロックの整合性を厳密に検証する AST レベルの木比較エンジン（`ast_tree.py`）を導入。
2. **ケバブケース意味的画像規約**: 正規表現検証（`^[a-z0-9]+(-[a-z0-9]+)*\.(png|jpe?g|webp|svg)$`）とアクティブなリンク整合性チェッカーを実装し、画像が適切に命名され、Markdown 内でインライン参照されていることを保証。
3. **テーブルセルアライメントスコア**: 行・列の次元一致度とセル内容の F1 重複度を個別に計算する評価モジュールを構築。

## ペルソナ 2: エンタープライズ IT & セキュリティインフラ監査人

### ペルソナの背景
規制業界（金融サービス、医療、防衛）における企業ソフトウェアガバナンスを統括。データ主権、プロプライエタリな形式（Visio、Project、Access）、および外部ネットワークへのデータ流出（エグレス）を厳格に監査。

### レビュー指摘事項と致命的フィードバック
> *「あまりにも多くの AI スタートアップがドキュメント変換を謳っていますが、その実態は生の機密ドキュメントを外部クラウドの LLM API に送信しているだけです。これは当行のセキュリティ基準では即座に却下対象となります。当行の基幹決済ネットワークを示す Visio (`.vsdx`) ダイアグラムはどう扱うのですか？Microsoft Project (`.xml`/`.mpp`) のスケジュールやレガシーデータベースのテーブルはどうですか？当社のパイプラインでは、外部ネットワーク送信ゼロで、これらをオンプレミス環境で決定論的にパースできなければなりません。」*

### 実装されたアーキテクチャの改善
1. **外部送信ゼロの純粋ソフトウェアリファレンスコンバーター**: OPC Zip アーカイブ（`.vsdx`, `.docx`）、Project XML スキーマ、SQLite/リレーショナルデータベースに対応したネイティブ Python パースモジュールを構築。外部 API キーやクラウド通信は一切不要。
2. **Visio ネットワークトポロジーパース**: `visio/pages/page*.xml` をネイティブにトラバースし、図面エンティティ、シェイプ接続、メディア要素を直接抽出。
3. **再現可能なローカルデータセットジェネレータ**: インターネットからプロプライエタリまたは著作権のあるサンプルドキュメントをダウンロードすることなく、全 8 種類のドキュメント形式をメモリ上で生成する `SyntheticDatasetGenerator` を同梱。

## ペルソナ 3: MLOps & プラットフォーム信頼性エンジニア

### ペルソナの背景
週あたり数百〜数千万ページを処理するバッチ取り込みパイプラインのパフォーマンス、メモリ安定性、スループット、およびクラウドコンピューティングインフラコストを担当。

### レビュー指摘事項と致命的フィードバック
> *「もしコンバーターが 1 ページに 10 秒もかかったり、50 ページの PowerPoint スライドで 2GB のメモリをリークしたりしたら、Kubernetes のワーカーポッドが OOM でクラッシュしてしまいます。正確な RSS メモリトラッキング、レイテンシの P50/P95 プロファイリング、そしてトークン肥大化が OpenAI や Anthropic の API 請求額に与える金銭的影響を可視化する経済モデルが必要です。」*

### 実装されたアーキテクチャの改善
1. **ランタイム＆メモリプロファイリング (`run_monitored`)**: すべてのコンバーター実行を `psutil` メモリサンプリング（最大常駐セットサイズ Peak RSS: MB）と高精度ウォールクロックタイマー（`perf_counter`）でラップ。
2. **マルチモデルコスト試算エンジン (`cost_eval.py`)**: `tiktoken` を統合して正確な BPE トークン数を計算し、GPT-4o、Claude 3.5 Sonnet、Gemini 2.0 Flash、DeepSeek-V3 における 1,000 ドキュメントあたりの入力コストをシミュレーション。
3. **スループットメトリクス**: 秒あたり処理トークン数（TPS）および秒あたり処理ドキュメント数をレポート。

## ペルソナ 4: オープンソース研究者＆ベンチマークメンテナー

### ペルソナの背景
マルチモーダル文書理解を研究し、コミュニティベンチマーク（OmniDocBench、DocLayNet 等）に貢献。数学的な再現性、モジュール型アダプター、直感的な CLI ユーザビリティを重視。

### レビュー指摘事項と致命的フィードバック
> *「ベンチマークツールが単一の特定パーサーに囲い込まれていてはなりません。Microsoft の MarkItDown、IBM の Docling、MinerU、あるいは自作の実験的 C++ パーサーを、まったく同じ評価ハーネスでテストしたいのです。標準化された CLI アダプターと、CI/CD パイプラインに取り込める出力アーティファクトを提供してください。」*

### 実装されたアーキテクチャの改善
1. **プラガブルアーキテクチャ (`CustomCommandConverter`)**: 任意の外部 CLI、スクリプト、コンテナ化パーサーを同一テストスイート上でベンチマークできる汎用コマンドテンプレートアダプター（`--converter custom --custom-cmd "my_tool {input} {output_dir}"`）を追加。
2. **自動化されたマルチフォーマットレポーティング**: Rich ターミナルスコアカード、GitHub 対応 Markdown サマリー、統計解析用 JSON/CSV ダンプ、インタラクティブな単一 HTML ダッシュボードの出力を実装。
3. **コマンドラインユーティリティ**: アドホック検証用の `aiready verify` と、2 つのコンバーター間のリグレッション比較を行う `aiready compare` を提供。
